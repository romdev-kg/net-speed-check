# net-speed-check

Консольный скрипт на Python, который замеряет скорость скачивания: 10 раз подряд скачивает файл по указанному адресу, каждый раз дожидаясь полного ответа, и выводит среднее время запроса, общий объём скачанных данных и скорость.

Нужен только Python 3.9+, внешних зависимостей нет.

## Запуск

```bash
python3 speedtest.py <адрес>
```

Пример:

```bash
python3 speedtest.py https://proof.ovh.net/files/10Mb.dat
```

```
[1/10] 10485760 байт за 2231 мс
...
[10/10] 10485760 байт за 2163 мс

Запросов:              10
Скачано всего:         104.86 МБ (104857600 байт)
Среднее время запроса: 2225 мс
Скорость скачивания:   37.70 Мбит/с (4.71 МБ/с)
```

Параметры:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `-n`, `--count` | `10` | сколько запросов сделать |
| `--timeout` | `30` | сколько секунд ждать данных от сервера, прежде чем считать запрос зависшим |

`--timeout` ограничивает ожидание сети, а не всё скачивание: большой файл на медленном канале может качаться дольше 30 секунд, и это не ошибка.

В адресе можно писать пробелы и кириллицу в пути — скрипт сам закодирует их.

## Единицы

- **Скорость** — в **Мбит/с** (мегабиты в секунду, 1 Мбит = 1 000 000 бит), как у провайдеров и speedtest-сервисов. В скобках та же скорость в **МБ/с** (1 МБ = 1 000 000 байт).
- **Объём** — в **МБ** (1 000 000 байт) и точно в байтах.
- **Время** — в **миллисекундах**.

## Что именно меряется

- **Время запроса** — от отправки запроса до получения последнего байта тела ответа: соединение, TLS, ожидание ответа и само скачивание. Каждый запрос открывает новое соединение, как обычная загрузка файла.
- **Объём** — байты тела ответа в том виде, в котором они пришли по сети. Скрипт просит сервер не сжимать ответ (`Accept-Encoding: identity`), чтобы скачивался реальный объём файла.
- **Скорость** — общий объём, делённый на суммарное время всех запросов.
- Запросы идут строго последовательно: следующий начинается только после того, как предыдущий ответ дочитан до конца.
- Тело читается кусками по 64 КБ и не держится в памяти целиком, поэтому подходят и большие файлы.
- Заголовок `Cache-Control: no-cache` просит промежуточные кэши не отдавать сохранённую копию.
- Разовая подготовка клиента (загрузка сертификатов, настройки прокси) делается до первого замера и в его время не попадает.

Так как в время запроса входит установка соединения, для оценки именно канала берите файл побольше — от нескольких мегабайт. На маленьком файле результат покажет в основном задержку до сервера, а не скорость канала.

## Ошибки

Если любой из запросов не удался, скрипт пишет в stderr, какой по счёту запрос упал и почему, и завершается с кодом `1`. Сводка по неполной серии не выводится: среднее по части запросов вводило бы в заблуждение.

Ошибкой считается:

- ответ сервера с кодом 4xx/5xx;
- недоступный адрес, обрыв соединения или таймаут;
- ответ, который оборвался раньше обещанного размера (`Content-Length`) — такой запрос не засчитывается как успешный замер;
- ответ не по протоколу HTTP.

Неверные аргументы (не `http/https` адрес, `--count` меньше 1, неположительный `--timeout`) дают подсказку и код `2`. `Ctrl+C` завершает скрипт с кодом `130`.

## Тесты

```bash
python3 -m unittest -v
```

Тесты поднимают локальный HTTP-сервер и проверяют, что:

- делается ровно 10 запросов и они не пересекаются во времени;
- объём и скорость считаются правильно;
- ошибка сервера, оборванный ответ и недоступный адрес дают код выхода 1 и понятное сообщение;
- адрес с пробелами и кириллицей кодируется, а неверные аргументы отклоняются.
